## Context and problem

Current drawings and the older default integration scenario resolve different source
states. Some quantity-family mapping and source-to-view relationships are implicit.
The owner authorized implementation of a connected, source-driven project workflow.

## Requirements that remain binding

The Constitution and source precedence remain in force. Preserve historical issues,
original Spanish evidence, active design authority and open conflicts. Author changes
in repository sources and explicit studies; generate SVGs from their resolved state.
Missing engineering data must remain unknown. Do not create branches.

## Alternatives and comparison

| Alternative | Consequence |
| --- | --- |
| Keep separate generators and manually reconcile every future change | Preserves the present tooling but retains duplicated state and review effort |
| Replace the entire project stack before delivering a connected case | Delays usable evidence and expands migration/dependency cost |
| Add a small shared adapter, pure evaluation/rendering and isolated candidate build | Reuses Python/JSON/SVG, makes the first propagation path testable and permits staged migration |

## Decision and basis

Implement the third approach through the existing phased plan. Use PB b37/P2 b28 and
their actual dependencies as the first current-source baseline; retain the original
D059 loader and issue history. Use canonical element identities with explicit aliases,
study preconditions, coverage-aware findings and generated views. Build complete
candidate packages before considering any explicit publication migration.

The owner's authorization concerns this software and information workflow. It does not
adopt synthetic test changes, approve a construction detail or close CF-009/010/011/012.

## Consequences and actions

The first increment is documented with commands, tests and a 27-output migration
inventory. Its runtime artifacts expose their source hashes and authority. Correct
workstation glazing classification while retaining unpriced/ineligible cost status.
Record CF-013 for the audited PB door-anchor inconsistencies; keep those endpoints
unresolved pending an explicit architectural reconciliation.
No construction scope, target, rate, saving, procurement authority or software spending
allowance is established. Remaining phase gates stay open in the plan; responsible
design professionals still supply and validate engineering inputs before those checks
can pass. Evidence of implementation is the source-to-view regression suite and
complete-package verification, not an automatic design approval.
